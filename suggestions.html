Public & auth pages24
Page or patternProposed change
Footer social links all public pagesFour social buttons point to “#”, so they look live but do nothing. Replace with real profiles, or remove the block until the accounts exist.
Home /The hero is strong, but ownership and proof arrive late. Add a compact proof row under the CTAs and give the hero image a real caption. Keep the marquee moving only when reduced-motion is off.
Course catalogue /coursesFilters are three full-width selects stacked above results on mobile — the first course sits ~500px down. Put search first, then a single scrollable filter row, and show the result count beside it.
Course detail /courses/[slug]On phones the enrolment card falls after the whole curriculum. Add a sticky bottom bar with price + enrol so the action is always one tap away; keep the rail sticky on desktop.
Services & Programs /servicesService rows read as a long list. Give each one an outcome line and a clear next step, and place the “talk to us” CTA after the second item on mobile.
Become a Mentor /mentorThe page explains the process but not the reward. Add a short “what you get” strip (paid role, assigned course, workspace) and keep the apply CTA visible on mobile with a bottom bar.
Team /teamPortraits are 80px thumbnails in a text list. A 3-up portrait grid with names and roles reads as a team page rather than a directory dump.
Partners /partnersGrouped logo lists are informative but visually flat. Add a count per group and a compact logo card grid so schools can scan for themselves.
About /aboutThe story and values are solid. Add a short timeline (founded → first school → mentor model) so the “education company that employs people” claim has a sequence, not just prose.
Contact /contactThe form is already two-column on desktop. On mobile, the “what we can help with” list sits before the form and delays the task. Put the form first on phones, details second.
Help & FAQ /faqSearch + category chips already work. Surface the five most-asked questions before the filter UI, and add a “still stuck?” contact card after the list.
Privacy · Terms · Refund /privacy · /terms · /refund-policyLong legal pages have no wayfinding. Add a sticky “On this page” index on desktop and a last-updated line at the top.
Sign in /loginA single centred card works, but desktop leaves half the viewport empty. Add a branded aside with one testimonial and three outcomes; keep the card first on mobile.
Create account /signupShow the three-step flow before the form (email → code → details) so the verification screen is expected, and add password guidance inline.
Forgot password /forgot-passwordAdd the expected timeline (“usually arrives in under a minute”) and a resend countdown so people do not hammer the button.
Reset password /reset-passwordShow password rules and a live strength meter before submit; disable the button until both fields match.
Verify email /verify-emailThe OTP flow is correct. Add the masked email to the heading, a resend countdown, and a “change email” link so a typo is recoverable.
Reactivate account /reactivateExplain exactly what is restored and what is not, and show the account email so people know which account they are reviving.
Complete registration /complete-registrationThe final step is the highest-anxiety screen. Keep a visible step count, show the verified email read-only, and put password rules beside the field.
OAuth callback /auth/callbackIt is a silent spinner. Add a status line and a fallback link after 10 seconds so a stalled OAuth round-trip is not a blank screen.
Checkout /checkoutOn mobile the summary and mentor picker stack before the pay button. Pin the total + pay action to the bottom and collapse the mentor list into a select.
Payment result /checkout/resultThe result screen is a single message. Add a receipt block (course, amount, order ref) and two explicit next actions: open course or retry payment.
Onboarding /onboardingThe two-step card has no progress signal. Add “1 of 2”, allow Skip, and preserve answers if the user refreshes.
404 / route errors not-found · global-errorKeep the illustration, but offer search and three likely destinations instead of a single “home” button.

Page or patternProposed change
Dashboard /dashboardThe hero and stat row are good. Turn the four counters into actionable tiles and add a “this week” goal so the page answers “what should I do now?”
My Learning /dashboard/my-learningEvery course renders the same card. Add progress-first sorting and tabs for In progress / Completed / Not started.
Course home /dashboard/courses/[slug]The three-column desktop layout is dense; on mobile the lesson list and chat stack without a clear order. Make the current lesson the first block and collapse curriculum into a drawer.
Lesson viewer /dashboard/courses/[slug]/lessons/[lessonId]Long lessons have no reading progress or persistent next action. Add a top progress bar and a sticky prev/next footer.
Roadmap /dashboard/courses/[slug]/roadmapThe timeline is readable on desktop but dense on mobile. Switch to a vertical stepper below lg and show only the current + next chapter until expanded.
Live sessions /dashboard/courses/[slug]/meetingsList rows show date and time but bury the join action. Add a state chip (Live / Starts in 2h / Recording) and one primary action per row.
Resources /dashboard/courses/[slug]/resourcesFiles render as a flat list. Group by week/type, show file size and type icon, and add a download-all action for mentors.
Progress /dashboard/progressThree stat cards plus course rows. Add one chart (lessons per week) so progress over time is visible, not just totals.
Orders /dashboard/ordersRows expand for details, but there is no receipt. Add a download invoice action on paid orders and a status timeline in the expanded panel.
Notifications /dashboard/notificationsFilter chips and mark-all work. Group items by day and add a per-item link target so a notification is actionable, not just readable.
Wishlist /dashboard/wishlistSaved courses should show price and a direct enrol action, not just a link back to the detail page.
Settings /dashboard/settingsThree stacked cards become a long scroll on mobile. Switch to tabs (Account / Mobile / Security / Notifications) and keep the danger zone last.
Profile /dashboard/profileAvatar, details, and edit form are separate cards. Add a completion meter and put “Edit” actions on each field group, not one global form.
Messages /dashboard/chatMobile already switches between thread list and conversation — good. Add unread badges, a typing indicator, and a date divider so long threads stay scannable.

Users /dashboard/admin/usersTable + mobile cards already exist — keep that. Add bulk selection, a role filter chip row, and make the email copyable.
User detail /dashboard/admin/users/[id]One long column mixes account, enrolments, and actions. Split into tabs and pin the destructive actions to a clearly separated danger zone.

Course editor /dashboard/admin/courses/new · /[id]The editor is a very long form with one save button at the bottom. Add a section index on the left and a sticky save bar; validate inline before save.
Roadmap builder /dashboard/admin/courses/[id]/roadmapChapter rows are tall and repetitive. Add drag handles, collapse rows, and show lesson counts per chapter in a compact header.
Participants /dashboard/admin/courses/[id]/participantsAdd progress bars, last-seen, and a CSV export. Keep the table scrollable on mobile, or switch to cards.
Mentors /dashboard/admin/mentorsCapacity is the key number but reads as a bare integer. Show a capacity bar and flag mentors at/over capacity.
Orders /dashboard/admin/ordersMoney and statuses are the whole point of this page. Add a status chip, filter row, tabular figures, and a receipt drawer instead of a modal wall of text.
